# AFAR_HPC

A reproducible OpenEvolve + ChampSim environment for SJSU CoE HPC. It is the foundation for evolving ChampSim cache-replacement policies with OpenEvolve, staged across GPU (generation) and CPU (evaluation) Slurm jobs.

This repository is at **Phase 0**: one command brings up a pinned toolchain, both Python environments and a working baseline ChampSim build. The experiment contract is recorded in [docs/experiment-contract.md](docs/experiment-contract.md) and is not implemented yet.

## What is pinned

| Component | Version | Pinned in |
|---|---|---|
| ChampSim | `410cee6` (upstream) | git submodule `external/ChampSim` |
| vcpkg (ChampSim's C++ deps) | `6d7bf7e` | ChampSim's own submodule |
| Compiler | Spack GCC 12.2.0 | `env/modules.sh` |
| Python | 3.11.5 | `env/modules.sh` |
| OpenEvolve | 0.4.0 (PyPI) | `env/controller-requirements.in` → `.txt` lock |
| ChampSim config | upstream default (1 core, no prefetch, LLC LRU) | `configs/champsim/baseline.json` |

`env/versions.txt` and `env/modules.lock.txt` record the environment the last time it was verified.

## Quickstart

```bash
git clone --recurse-submodules <repo-url> AFAR_HPC
```

```bash
cd AFAR_HPC && make setup
```

`make setup` takes about 15 minutes the first time. It needs no Slurm allocation; builds run on the login node with `-j2`. Each step runs in order and stops at the first failure:
1. fetch the submodules
2. create `.venv/controller` and `.venv/evaluator` from the lock files
3. install ChampSim's C++ dependencies with vcpkg
4. build `build/baseline/champsim`
5. run `make check`

To work interactively (modules plus the OpenEvolve venv):

```bash
source env/activate.sh
```

An optional seconds-long sanity run of ChampSim (traces are not in the repo):

```bash
make smoke TRACE=/path/to/602.gcc_s-1850B.champsimtrace.xz
```

Anything longer than `make smoke` belongs in a Slurm allocation, not on the login node.

## Make targets

| target | does |
|---|---|
| `setup` | `submodules venvs vcpkg champsim check` |
| `submodules` | `git submodule update --init --recursive` |
| `venvs` | create both venvs from `env/*-requirements.txt` |
| `vcpkg` | bootstrap vcpkg and install ChampSim's dependencies (`--clean-after-build`) |
| `champsim` | `config.sh` + `make` with `configs/champsim/baseline.json` → `build/baseline/champsim` |
| `check` | verify modules, pinned submodules, venvs vs locks, OpenEvolve, baseline binary |
| `smoke TRACE=…` | 10K warmup + 10K simulated instructions, JSON output parsed |
| `env-record` | rewrite `env/modules.lock.txt` and `env/versions.txt` |
| `lock` | re-resolve `env/*-requirements.in` into the `.txt` locks |
| `modules-save` | also save the module set as a personal Lmod collection `afar-hpc` |
| `clean` / `distclean` | remove build outputs / also the venvs and `vcpkg_installed/` |

Set `JOBS=N` to change build parallelism (default 2).

## Layout

```
env/
  modules.sh                    the module set; sourced by make, activate.sh, and future sbatch scripts
  activate.sh                   modules + controller venv
  controller-requirements.in    OpenEvolve (edit this)
  controller-requirements.txt   pinned lock (generated by `make lock`)
  evaluator-requirements.in     ChampSim-side Python deps (stdlib only for now)
  evaluator-requirements.txt    pinned lock
  check.sh, lock.sh, record-versions.sh
  modules.lock.txt, versions.txt   recorded evidence (generated by `make env-record`)
configs/champsim/baseline.json  ChampSim configuration for baseline builds
docs/experiment-contract.md     candidate format, manifest, result schema, fitness, failure policy (v0)
external/ChampSim/              ChampSim submodule
```

## Environment rules

- **Load the modules before using a venv.** `source env/activate.sh` does this. Batch scripts must `source env/modules.sh` themselves, because a job does not inherit your login shell.
- `env/modules.sh` runs `module use` on the Spack module tree explicitly. That tree is on `MODULEPATH` on the login node, but it has been missing inside batch jobs.
- **pip installs wheels only** (`--only-binary=:all:`). The cluster's glibc 2.17 cannot use the newest numpy wheels, so the lock resolves numpy to 2.2.6 rather than trying a source build.
- **Venvs are disposable.** To recreate them, run `make distclean setup`, or delete `.venv/` and run `make venvs`.

## Changing a pin

- **Python packages:** edit `env/<role>-requirements.in`, run `make lock venvs check`, and commit both the `.in` and `.txt` files.
- **ChampSim:**
  1. `git -C external/ChampSim checkout <commit>`
  2. `git submodule update --init --recursive`
  3. `make vcpkg champsim check`
  4. commit the submodule change
- **Modules:** edit `env/modules.sh`, run `make distclean setup env-record`, and commit.

## Porting to another cluster

Edit only `env/modules.sh`. It must provide:
- Python ≥ 3.10 (required by OpenEvolve)
- a C++17 compiler (GCC 12.2 is known good)
- git ≥ 2.7 (required by vcpkg)

Then run `make setup`. If the new cluster has a newer glibc, `make lock` may resolve newer wheels. Commit the regenerated locks on a branch for that cluster.
